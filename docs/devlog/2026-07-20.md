# 2026-07-20 Devlog

## Gate failure → full split-vs-combined edit comparison → Rev 2.8 key restoration

### Context

The 07-18 Mac gate attempt failed on dead add fields (Cmd-Return armed a field
typing couldn't reach), and two days of focus-machinery patching went nowhere.
Gaylon stopped the cycle and ordered a step-way-back: read the CODE of the last
split-function version (edit mode "worked perfectly") and diff every edit
function against the combined editor. No guessing, no memory, no logs — code.

### The comparison (both versions inventoried function-by-function from git show)

Reference: `2b73f6d` (last commit before `2cb9946` deleted check mode; also the
commit that recorded the Gate M1 macOS pass — i.e. user-validated editing).
Result: **every edit function except item creation was equal or better in the
combined editor.** Select, multi-select, rename mechanics, commit/cancel,
click-away commit, Tab/Shift-Tab, delete, move, drag, expand/collapse, Escape,
and the add-field's commit-and-continue loop — all behaviorally identical.

The regression was exactly two entangled changes:

1. **M5 rebound Return from "add below" to "rename"** and deleted Shift-Return
   (add above) entirely, leaving NO editor-owned key that creates an item
   relative to the selection.
2. **The replacement keys (Cmd-N / Opt-Cmd-N / Cmd-Return) are menu
   equivalents** — and menu dispatch demonstrably cannot hand first responder
   to a newly mounted field on this OS (FocusState reports focused; AppKit
   responder never moves; no focus-change event ever fires). The old version's
   primary adds never touched that route; only Cmd-Return did, latently.

Clarifying rule that fell out: the menu route only breaks commands that must
**end with a cursor in a text field**. Pure actions (toggle, delete, move,
indent) work fine through menus — which matched everything Gaylon observed.

### Decisions (Gaylon)

- **Old bindings back** (spec Rev 2.8, fixed decision 3 REVERSED): Return =
  add below, Shift-Return = add above + immediate rename, Cmd-Return = add
  child now ALSO editor-owned; rename = double-click / Cmd-E. Cmd-N and
  Opt-Cmd-N stay as secondary menu routes.
- **Bare Space toggle RETAINED** (initially slated for removal): Gaylon
  verified it never fires during text entry (field consumes it + the
  isTextInputActive guard) and toggles only after Return/Esc — "standard
  control, I really like the convenience." Now an explicit gate assertion.
- The td-ff531e focus machinery (NSMenu didEndTracking re-assert, responder
  fallback) was hands-on validated by Gaylon on 07-19 and committed as the
  baseline (`597c98e`) — it stays, now serving the menu-clicked paths.

### Implementation

`handleReturnKey` restored to 2b73f6d semantics + editor-owned Cmd-Return;
CommandCatalog editorOwnedKey/help updates (newItem "Return", addAbove
"⇧Return", rename none); parity matrix Key column; gate checklist §B rewritten
in both md and OPML (Return-primary adds hammered ×10, menu routes as a
separate step, Space both-halves check); spec Rev 2.8 note. Tests:
testReturnRenamesSelectedRow replaced by testReturnAddsItemBelowSelection +
testShiftReturnAddsRenameableItemAbove + testCommandERenamesSelectedRow, all
with typing-lands focus proofs; new testEditorOwnedKeyAssignments pins the
binding decision.

### Process note

The two-day focus-patching spiral was compensation in the wrong layer —
extending focus machinery instead of questioning the trigger-path change that
made it necessary. The comparison that broke the spiral took one session and
started from "read the last-known-good CODE, not your assumptions." That is
cs.md's evidence mandate applied to design archaeology, and it should be the
FIRST move next time a working feature degrades across a refactor.
